RISK

Flutter のバージョンが古いと、何が危ないか

ブラウザや OS の部品はメーカーが自動で更新しますが、Flutter で作ったアプリは違います。通信や画像の処理に使う部品をアプリ自身が抱えているため、アプリを作り直さない限り、古い部品のまま動き続けます。

通信の安全性Android・Windows・Linux では、信頼する証明書の一覧をアプリの中に持っています。認証局が侵害されても、古いアプリは偽の証明書を信じ続け、通信を盗み見されたり書き換えられたりするおそれがあります。
例：2026年10月の eMudhra 認証局の侵害（Flutter 3.47.8 で修正、GHSA-frr6-h895-5pxp）
画像の処理画像の読み込みや描画のためのライブラリ（Skia・libpng・libwebp など）を同梱しています。細工した画像を表示させるだけで、アプリが落ちたり、最悪の場合は任意のコードを実行されたりするおそれがあります。
例：WebP の脆弱性 CVE-2023-4863、Skia の CVE-2023-6345、libpng の脆弱性（Flutter 3.47.2 で修正）
Dart の標準ライブラリURL の解析や検証の不具合で、本来は弾くべき URL が通ってしまうことがあります。
例：dart:uri の認証回避の脆弱性
ストアの要件Apple と Google は、新しい SDK でのビルドを定期的に義務づけています。Flutter が古すぎると、緊急の修正が必要なときにすぐ出せません。
例：Xcode 27 では古い設定のままではビルドが通らず、追加の対応が必要でした

参考：Flutter の CHANGELOG とセキュリティ勧告（GitHub Security Advisories）。正確な情報は Flutter 公式の発表でご確認ください（2026年11月10日時点の情報です）。

CHECK

こんなアプリは、すぐに確認を

  • Flutter で作ったアプリを App Store・Google Play で公開している
  • アプリで使っている Flutter のバージョンを把握していない
  • 公開してから、半年以上アプリを作り直していない
  • ログイン・決済・個人情報をアプリで扱っている
  • 制作会社と連絡がつかず、保守する人がいない
  • ビルドが通らず、更新版を出せなくなっている

SERVICE

対応内容

01現状の確認

Flutter・Dart のバージョン、依存パッケージ、iOS・Android のビルド設定を洗い出し、該当するセキュリティ勧告と更新の影響を見積もります。

02Flutter・Dart の更新

Flutter を stable の修正版へ更新します。古いバージョンからは段階的に上げ、依存パッケージもあわせて更新します。

03ビルドの対応

Xcode・CocoaPods、Android Gradle Plugin・SDK のバージョンなど、新しい環境でビルドが通らない箇所を直します。

04アプリの動作確認と修正

iOS・Android の実機で主な画面と機能を確かめ、動かない箇所や非推奨になった書き方を修正します。

05ストアへの再申請

App Store・Google Play へ更新版を申請し、審査で指摘があれば対応して、公開まで見届けます。

06今後の更新の仕組みづくり

修正版をこまめに取り込む手順や、セキュリティ勧告を定期的に確認する運用をご提案します。

FAQ

よくある質問

利用者がスマートフォンの OS を更新すれば、Flutter の脆弱性は直りますか？

直りません。Flutter の多くの部品はアプリの中に組み込まれて配られるため、Flutter を更新してアプリを作り直し、ストアに出し直す必要があります。

他社が作った Flutter アプリでも対応できますか？

はい。ソースコードと、ストアの開発者アカウントへのアクセスをご用意いただければ対応します。制作会社と連絡が取れない場合もご相談ください。

Flutter を何世代も更新していません。対応できますか？

はい。Flutter・Dart と依存パッケージを段階的に上げ、非推奨になった書き方や、Xcode・Android Gradle Plugin の設定を直しながら進めます。

どのくらいの期間で対応できますか？

アプリの規模と、どれだけ古い Flutter を使っているかによって変わります。ストアの審査にも日数がかかります。まずは現在の構成を確認して、作業日数とお見積りをお伝えします。
