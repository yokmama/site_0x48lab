PHPの重大な脆弱性（2026年10月公表）

PHP2Shell の対策を、
PHPの更新から動作確認まで。

「PHP2Shell」（CVE-2026-109618 / CVE-2026-109619）は、PHP本体の重大な脆弱性です。WordPress やプラグインの更新だけでは直らず、PHPそのものの更新が必要です。ハックラボは、PHPの更新と、WordPress・Laravel などのサイトが新しいPHPで正しく動くかの確認、データベースの更新、侵害の痕跡の確認までをまとめて引き受けます。

ABOUT

PHP2Shell とは

2026年10月21日に PHP の開発チームがセキュリティ修正を公開した、PHP本体の脆弱性2件の通称です。条件がそろうと、ログインなしで外部からサーバー上のプログラムを実行される（リモートコード実行）おそれがあります。

CVECVE-2026-109618 / CVE-2026-109619
深刻度CVSS v4.0 で 9.2
修正版PHP 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12
8.1 以前サポートが終了しており、修正版は出ません。サポート中のバージョンへの移行が必要です
影響が報告された構成mod_php、php-fpm、WordPress、Laravel、Symfony など
悪用の状況攻撃コードが出回っていると報告されており、米国 CISA は悪用が確認された脆弱性の一覧（KEV）に登録しています

設定の変更で一時的に危険を下げる方法も紹介されていますが、どれも完全な対策ではありません。根本的な対策は PHP を修正版に更新することです。また、更新の前にすでに攻撃を受けていないか、ログを確かめることも勧められています。

参考：GMO Flatt Security Blog、AWS ブログ、＠IT。正確な情報は PHP 公式と JVN のアドバイザリでご確認ください（2026年11月7日時点の情報です）。

CHECK

  • WordPress で作ったサイトやブログを運営している
  • Laravel など PHP で作った業務システムがある
  • サーバーの PHP のバージョンを把握していない

  • 制作会社と連絡がつかず、保守する人がいない
  • 更新したいが、サイトが壊れないか心配

SERVICE

対応内容

01現状の確認

PHP のバージョンと動かし方（mod_php / php-fpm）、サーバーの種類、WordPress・Laravel・プラグインのバージョンを洗い出し、更新の影響を見積もります。

02PHP の更新

PHP を修正版へ更新します。8.1 以前の場合は、サポート中のバージョンへ移行します。更新の前にバックアップを取り、戻せる状態で作業します。

03サイトの動作確認と修正

WordPress のテーマ・プラグイン、Laravel のアプリが新しい PHP で動くかを確かめ、動かない箇所は修正します。

04データベースの更新

MySQL・MariaDB などのデータベースも、必要に応じて新しいバージョンへ更新します。

05侵害の痕跡の確認

アクセスログや不審なファイルを確かめ、更新の前に攻撃を受けていないかを調べます。

06再発を防ぐ設定

Cloudflare などによる防御の設定や、今後の更新の進め方もあわせてご提案します。

FAQ

よくある質問

WordPress のプラグインを更新すれば PHP2Shell は防げますか？

防げません。PHP2Shell は PHP 本体の脆弱性なので、PHP そのものを修正版（8.2.35 / 8.3.36 / 8.4.27 / 8.5.12 以降）に更新する必要があります。

PHP 8.1 以前を使っています。どうすればよいですか？

PHP 8.1 以前はサポートが終了しており、修正版が提供されていません。サポート中のバージョンへの移行が必要です。WordPress や Laravel、プラグインが新しい PHP で動くかを確かめながら移行します。

共用レンタルサーバーでも対応してもらえますか？

はい。サーバーの管理画面で PHP のバージョンを切り替えられる場合は、切り替えとサイトの動作確認を行います。サーバー会社側の対応状況もあわせて確認します。

どのくらいの期間で対応できますか？

環境によって変わります。WordPress・PHP・データベースの更新は、状況によって2〜3日以上かかる場合もあります。まずは現在の環境を確認して、作業日数とお見積りをお伝えします。
